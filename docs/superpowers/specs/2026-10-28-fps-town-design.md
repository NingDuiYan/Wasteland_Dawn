# 求生 Survival — 第一人称射击设计文档

- 日期：2026-10-28
- 状态：已实现并浏览器实测通过（第一人称 / 3D / 无外部素材）
- 类型：浏览器第一人称射击（Three.js WebGL2），程序化生成的废土小镇
- 取代：`2026-10-26-wasteland-dawn-design.md`（斜俯视 2.5D 守家方案）、`2026-10-27-visual-atmosphere-design.md`（Phaser 渲染管线方案）

## 1. 为什么转向

项目最初是 Phaser 2.5D 顶视角守家游戏，资产全部来自 Kenney CC0 贴图。三件事导致整体重做：

1. **视角**：斜俯视投影做出来的画面始终读作"平面地图"，改投影系数、改素材都救不回来
2. **素材**：后续找到的风格参考（饥饿式手绘墨线）没有可用的免费素材，自己用 Python 画到第 6 版仍达不到要求
3. **网络**：素材站在开发环境被 TLS 阻断，无法引入新的外部资源

结论：删掉全部素材与 Phaser，改成 **Three.js 第一人称**，场景中的每一个物件都用代码按固定种子生成 —— 零外部素材、可离线、刷新后布局完全一致。

## 2. 核心循环

```
开局（傍晚 15:36）
  → 在小镇街道上探索，遇到丧尸
  → 左键射击、R 换弹，边打边退
  → 天黑（约 1 分钟后），能见度骤降，丧尸视野变大
  → 撑到天亮（夜里约 4 分钟）或被打死
死亡
  → 结算击杀数，按 R 重开
```

- 一整天 **600 秒**（游戏内 1 小时 = 25 秒）
- 开局时间 **15.6 时**：既看得到完整的黄昏过渡，也不会让人干等白天
- 丧尸 **常驻 12 只**：野外击杀后隔 5 秒在玩家 34~72 米外补一只（永远在视野外冒出来，不在脸上凭空出现）
- 昼夜影响丧尸索敌距离：白天 26 米，夜里 46 米

## 4. 程序化小镇

唯一入口 `createTown(seed = TOWN.seed): TownLayout`（`src/sim/town.ts`）。生成顺序是这类小镇唯一可靠的做法：

```
划街道（5 条，等距 44 米）
  → 街道之间自然形成 4×4 个街区
  → 街区再切成地块（带 2.2 米过道）
  → 地块里放建筑（house / shop / shed，朝街一面为 front）
  → 沿街摆路灯、停车、巷子里塞桶/箱/垃圾
  → 最后收集所有碰撞盒 colliders
```

- 先划街再放房，就不会出现"房子压在马路中间"
- 每栋楼记录 `front`（朝街方向），门的朝向由它决定
- 布局里同时产出 `props`（物件）与 `colliders`（碰撞盒），渲染层与物理层读同一份数据，永远不会错位

## 5. 渲染管线

### 场景装配顺序（`src/render/app.ts`）
```
createGround   →  一张 1760px 烘焙贴图铺满整个世界（不重复采样）+ 法线贴图
createSkyline  →  46 栋远景剪影，挡住地平线
buildTown      →  建筑/道具/路灯（InstancedMesh 合并窗户与灯泡）
ZombieView     →  低模人形
SkyRig         →  太阳/半球光/雾/天球
ViewModel      →  挂在相机上的 8 件武器（默认 AK47 突击步枪）
PostFX         →  全屏后处理
```

### 光照与阴影
- 一盏平行光当太阳，按小时算角度（`arc = (hour - dawn) / (dusk - dawn) * PI`）；**不能用"日照强度"当角度** —— 强度最大时太阳正好趴在地平线上，最亮的时候反而最黑
- 天顶色 = 雾色压暗后往 `SKY.zenith` 蓝调上 lerp；只压暗不调色，天空就是一块灰幕
- `FogExp2` 密度 `0.0034 + (1 - daylight) * 0.0052 + fogAlpha * 0.03`
- 阴影：512 阴影贴图 + 正交相机覆盖全镇 + `normalBias 0.4`
- 夜里窗玻璃与路灯用 `emissiveIntensity` 点亮（不是加真实光源），只有玩家 40 米内最近的一盏路灯会挂一盏真实 `PointLight`

### 后处理
`src/render/effects.ts` 里是**纯字符串的效果体**，两种渲染路径共用（Phaser 时代留下的结构，现在只有 Three 用）：

- `POSTFX_UNIFORMS` / `POSTFX_FUNCS`（hash、rainLayer、lightMask、refractUv）/ `POSTFX_APPLY`（`vec3 applyPostFx(vec2 uv, vec3 color)`）
- 效果顺序：雨幕折射 → 饱和度 → 色偏 → S 曲线对比度 → 闪电 → 颗粒 → 暗角 → 夜色与光斑
- **色彩空间坑**：three 往 RenderTarget 写的是线性值，而参数是在 sRGB 显示空间调的着，所以片元里先 `pow(linear, 1/2.2)` 再进效果体；RenderTarget 必须标 `LinearSRGBColorSpace`，标 sRGB 会二次解码变暗
- 光斑在世界空间定位：`projectLight` 把光源世界坐标用相机 `project()` 到屏幕 uv，再换算成像素半径 —— 这样手电/路灯的光斑能钉在场景里而不是黏在屏幕上

### 视图模型造型（`src/render/viewmodel.ts` + `weaponParts.ts` + `ak47.ts`）

动作层与造型层分开：`viewmodel.ts` 只管 `REST = (0.27, -0.27, -0.5)`、`SCALE 0.66`、pivot 的 `set(0, -0.1, 0.02)` 与 `MOTION` 表；造型由 `BUILDERS[id]` 建，几何与材质在 `weaponParts.ts` 里记账，切枪时整批 `dispose()`（只摘 mesh 会漏显存）。造型复杂的枪单独开文件，目前只有 `ak47.ts`。

**AK47 还原口径**（米，枪口朝 -z，膛线轴 y = +0.040；总长 0.910 = 托 0.253 + 机匣 0.262 + 前段 0.395，木托:机匣 0.97 与实枪一致）：

- 发射点 `(0, 0.04, -0.56)` 与旧步枪同一坐标，火光 / 曳光 / 弹道零改动
- 玩家看到的是**枪的左侧 + 顶面**；+x 侧的快慢机与拉机柄永远在背面（形状仍建全，不能缺件）
- 识别度按屏幕面积排序：香蕉弹匣（三段折线、包角 32°、底缘前移 0.067）→ 木护木 / 皮革 / 钢的色块节奏 → 圆顶防尘盖（**必须用 tube**，用 box 会被读成平顶 M16）→ 导气箍台阶 → 照门座 → 握把后倾 24° → 通条 → 斜切枪口
- 关键判据：机匣含防尘盖高 0.060、膛线轴到机匣顶 0.030、准星护耳间隙 ≥ 0.012、弹匣每段轴向重叠 0.010（14° 折角会在接缝张开 7.5 毫米亮缝）
- 旧化全部用几何薄片：枪托 6 圈布条（间距不等、深浅交替）、护木包皮革 + 2 道锈铁丝、弹匣下半截 2 圈胶带；配色从 `PALETTE` 派生，不写裸十六进制
- 这个距离上机匣处约 586 像素/米、枪口处 352 像素/米，**小于 8 毫米的特征等于没做** —— 所以没做铆钉与托底板细节，也没引入贴图

### 性能与降级
- 无头 Edge（`--disable-gpu`，SwiftShader 软件光栅）1280×720：开阴影 38~43 FPS、关阴影 60 FPS；阴影贴图 1024→512、PCFSoft→PCF 对帧数影响都很小，**瓶颈是整个阴影 pass 的几何量，不是分辨率**
- 因此加了运行时兜底：**运行 6 秒后若 FPS < 45，自动关掉阴影并把所有 `castShadow` 清掉**（宁可没阴影也不卡）
- 真实显卡下应稳定 60

## 8. 已实现的细节亮点

- **丧尸模型面向 +z**，`yaw = atan2(dx, dz)` 直接对应 `group.rotation.y`；模型朝向和 sim 的约定不一致是这类项目最常见的"丧尸倒退着走"
- **射线分两层**：先算丧尸胶囊体最近交点，再算所有 `colliders` 的 box 交点，取更近的那一个 —— 隔着墙打不到人
- **死亡尸体仍参与碰撞**吗？不：`dead` 后停止移动与攻击，2.2 秒后回收并补刷
- **走路镜头起伏**：`bobAmplitude` 的正弦叠加到眼高上，同时轻微 roll；没有它第一人称像摄像机在冰面上滑
- **枪模单独打光**：`camera` 上挂一盏距离 1.6 米的小点光源只照手里的枪，否则世界一暗枪就是一块黑
- **枪模缩小到 0.66**（`SCALE`）：枪离眼睛只有半米，按真实尺寸画会挡住半边屏幕；位置是 `REST = (0.27, -0.27, -0.5)`、pivot 再歪 `(0, -0.1, 0.02)`，所以画面里只看得到枪的左侧与顶面
- **AK47 的圆顶防尘盖必须用 tube**：机匣顶上那条拱形是 AK 的第一识别特征，用 box 会被读成平顶的 M16
- **旧化不用贴图，用几何薄片**：枪托 6 圈布条、护木包皮革 + 2 道锈铁丝、弹匣两圈胶带 —— 这个距离 1 毫米才 1 像素，读得出的只有色块节奏与形体轮廓
- **香蕉弹匣要三段重叠**：3 段折线拼成 32° 包角，每段沿轴向压 0.010，否则 14° 折角会在接缝张开 7.5 毫米的亮缝
- **暴雨夜比晴天夜更暗**：`darkness = max(天气暗度, 夜晚系数 × 0.42)`

## 9. 实测教训（勿重蹈）

1. **太阳角度用小时推，不要用日照强度**：强度最大时太阳在地平线，画面最暗
2. **天顶必须单独调色**：只把地平线色压暗会得到一块灰幕
3. **阴影视差要用 `normalBias`**：只调 `bias` 会在墙面留下规则的条纹状漏光
4. **天空球跟着相机**：天球不跟随的话，走出中心区域就能看到球的边缘
5. **相机背后不要投影光斑**：`project()` 在 z > 1 时要把光强清零，否则身后的光源会在屏幕中间糊出一团亮斑
6. **地面平面默认以原点为中心**：Three 的 `PlaneGeometry` 是居中的，如果世界坐标是 0..N，要自己挪到 N/2，否则只有四分之一在画面里（这个坑在 2.5D 时代也踩过一次）
7. **纹理平铺的无缝靠"周期性噪声 + 3×3 重复绘制"**：元素坐标必须先算好再重复画，否则每份副本形状不同，接缝照样在
8. **`THREE.Clock` 在 r186 已废弃**：用 `THREE.Timer`（它挂 Page Visibility，切标签页回来不会甩出一个巨大的 delta）
9. **`tools.edit` 遇到 Windows 文件占用报 `ReplaceFileW EIO (Win32 1175)`**：同一调用重试即可
